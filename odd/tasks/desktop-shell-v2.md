# Desktop shell v2
Implement the approved design `design/gentle-desktop-shell-v2/01-compact-three-pane.html` in the real stack, trim Desktop-irrelevant commands, and show real state only.
Branch: `integration/desktop-mvp`; delivery: local work-unit commits, no push/PR; runner: Vitest (`node node_modules/vitest/vitest.mjs run`), `node node_modules/typescript/bin/tsc --build --force`, Electron smoke with the local dist. Visual spec: the artboard; tokens: `design/system.md`.

## Specs
S1. "hay comandos que traemos de gentle-shell que en realidad no son utiles en gentle shell desktop, como el tema de animations" "lo de VIm porque no tiene sentido si vamos a hacer nuestro propio editor pequeño" "lo que digiste de comandos que sobran en desktop lo de la tabla estoy totalmente de acuerdo". Approved table: remove from the Desktop UI (not from gentle-shell, the home is shared with the terminal) `gentle:vim`, `gentle:animations`, `gentle:double-esc-cancel` (also from the Settings catalog); hide from the slash menu `gentle:customize`, `history`, `gentle:status-timing`, `gentle:dev-binary`, `gentle:scratch` and the doubtful `gentle:doctor`, `gentle:status`, `gentle:telemetry`; keep `gentle:persona`, `gentle:mode`, `gentle:yolo`, `gentle:review-mode`, `gentle:background-subagents`, `gentle:profiles`, `skill-registry:refresh`. A short hide-list with a "show all" toggle, never an allowlist: user skills and prompts always show.
S2. "La barra superior personalizada de Electron que no sea el generico de electron sino ya propia o que usé los colores de gentle shell desktop y sea más una app de escritorio pura". Artboard: frameless title bar, brand and left-panel toggle on the left; Agents & jobs, Settings (the ORIGINAL gear icon: "Este no es el icono de settings que ya estaba no?") and right-panel toggle on the right; window controls painted with theme colors; the center stays EMPTY (drag area): "Esto mejor no, porque para eso está lo de tipo shell abajo que dice Settings with no chat Open no?". No theme switcher anywhere in the bars: "Esto no lo pedí verdad, porque la idea es que se pueda configurar desde settings".
S3. "abajo en la barra donde está el tema de contextp y etc se puede poner tipo el nombre de la memoria de engram de ese chat, por ejemplo el de ahorita de nosotros se llama creo integration-desktop-mvp ° y el check saved y todo como gentle-shell". Status bar per the artboard: folder, `branch: <name>`, Engram segment (gentle-engram publishes `setStatus` key `engram`, text `<project> · <action>`; show verbatim without the emoji, brain icon drawn, never parse the project name), and model/effort/context ONLY when the RPC exposes them (product principle: show only real state; no sample values).
S4. "sería mejor que eso sea para agents o jobs y que abra una ventana tipo settings haciendo algo similar a agentes y jobs, pero uniendo ambos en una ventana". The title-bar button opens an "Agents & jobs" settings-style window: list with filters on the left, detail on the right, read-only. Agents come from `HelperTask`. Jobs are not in the bridge today: they ship only when gentle-shell exposes them (investigate first); until then the window lists agents only and never shows sample jobs.
S5. Layout, Files and Git per the artboard (backlog B2-B7): remove "Chat in another folder..." entry; bars lower (title bar 36 px, status bar 28 px); composer hints on ONE line; Files tab with file and folder icons and icons on the Files and Git tab headers; Git tab shows branch, changes with status letters and recent commits, READ-ONLY (stage, commit, Push, Pull and Sync are high-risk writes and come later, agreed order); Models opens as a settings-style modal.
S6. "al tocar un archivo en files poder editar el codigo como un editor externo, como Orca, puede ser con CodeMirror 6 o algo que sea mejor y no genere perdida de rendimiento". Agreed: ship the Read mode first (read-only viewer, same path confinement as Files); Edit and Save come later (first write to disk). CodeMirror 6 loaded lazily only when a file opens.
S7. Handoff text, verbatim: "Implement it in the project's real stack. Use the artboard as the visual spec: map its parts to the project's existing components and styles, and do not copy the artboard HTML verbatim. Take colors, typography, spacing, radius and shadows from design/system.md, the project's token source."
